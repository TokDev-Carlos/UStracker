## R11 — Core operational flow

GOAL: Client → Company → Vehicle/Fleet → Monthly Plan → Subscription → Payment → Finance → Overview works as one coherent transaction chain.

### Requirements
- R11-01 From Client Profile, action `Nova Assinatura` uses current client context; do not reselect client.
- R11-02 Only Monthly catalog items are selectable for subscription.
- R11-03 User selects eligible client vehicles and/or fleets.
- R11-04 Commercial > Nova Assinatura supports inverse flow: search client → plan → mobility → terms.
- R11-05 Both entrypoints call one backend/domain operation.
- R11-06 Subscription stores effective value, start date, linked mobility and plan.
- R11-07 Successful payment propagates to Financial and Overview without duplicate writes.
- R11-08 Fleet/vehicle screen clearly exposes client/company/current subscription relations.
- R11-09 Legacy routes remain compatible.

TESTS:
- client-context subscription creation
- commercial-context subscription creation
- monthly-only plan filter
- particular vehicle subscription
- fleet subscription
- invalid cross-client mobility rejection
- duplicate/idempotent create
- payment propagation
- audit event

GATE: complete scenario from fresh client to reflected overview succeeds without manual data patch or refresh.

## R12 — Real-time client/entity search

GOAL: Replace large dropdowns/toggles with reusable bounded autocomplete.

### Contract
- Component/service: `EntityAutocomplete` or equivalent reusable abstraction.
- Client search fields: normalized name, document, company, phone where available.
- Case-insensitive and accent-insensitive.
- Debounce 150–300 ms.
- Server-side/bounded results; default limit <= 30.
- Keyboard: ArrowUp/ArrowDown/Enter/Escape.
- Clear restores state.
- Empty input must not materialize all customers into DOM.
- Typing `Car` returns matching names; `Carlo` narrows immediately.

TESTS:
- 1000+ fixture records without 1000 DOM options
- accents/case
- incremental query narrowing
- keyboard selection
- stale-response race protection
- network/API error state

GATE: all client selectors in active workflows use the reusable search pattern.

## R18 — Overview 2.0

GOAL: Answer operational/financial state for all-time or selected year.

### Top KPIs
- Receita Geral
- Despesas Gerais
- Resultado
- Clientes Ativos
- Veículos

DESPESAS = realized/recognized expenses according to finance ledger contract.

Drilldown endpoints/details must expose components and prevent double counting.

## R22 — Transactional updater

GOAL: Replace arbitrary copied installations with versioned update transaction.

Required flow:
1. read current version
2. fetch/read update manifest
3. compare semver/product version
4. download to bounded temp location
5. verify checksum + signature where supported
6. validate schema compatibility
7. backup data
8. stop/lock app
9. stage files
10. atomically activate update or bounded file replacement
11. restart
12. health check
13. on failure rollback application version and preserve data
14. log update result

Artifacts:
- VERSION.json
- current.json
- manifest/update package
- hashes/signature metadata

Rules:
- application rollback != data backup
- no `UStracker-Copia`, `Final`, `Novo`, etc.
- stale staging directories cleaned safely
- updater respects portable APP_ROOT

TESTS: no update, valid update, bad hash, bad signature, incompatible schema, interrupted apply, failed healthcheck, rollback success.
