# UStracker Public Release Sanitization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Publish UStracker 1.00.01.000 from the functional package as a clean, reproducible GitHub Release without operational UserData, credentials, workstation identity, browser state, or other private runtime artifacts.

**Architecture:** Recover only source/runtime-independent application files from the verified functional package into an isolated release branch. Treat `UserData` as runtime-only state, hard-fail release packaging if any file appears beneath it, align release metadata with database schema v3, validate the reconstructed source and Windows portable artifact in GitHub Actions, then merge to `main` and publish the manually gated Release.

**Tech Stack:** Python 3.13, FastAPI/Uvicorn, JavaScript ES modules, .NET/WPF/WebView2, PowerShell 5.1-compatible packaging, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-16-public-release-sanitization-design.md`

## Global Constraints

- Version remains `1.00.01.000`.
- Database schema is version `3` after recovery.
- No operational file may be present beneath `UserData/` in a public release ZIP.
- The public artifact must be generated by CI from source, never from the previously executed installation ZIP.
- Existing public update verification key remains public; no private signing key is committed.
- `main` is updated only after source recovery and verification succeed.
